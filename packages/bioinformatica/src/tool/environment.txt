Inspect the local environment for running nf-core pipelines and report what is present.

This tool is read-only: it runs version/inspection commands (nextflow, java, nf-core, docker, conda/mamba, nvidia-smi) and reads CPU/memory and platform facts. It never installs, changes, or writes anything.

Use it before proposing or running a pipeline, or when diagnosing an environment/version/resource problem, so you reason from the actual machine state rather than assumptions. It returns:
- the platform: Linux, macOS, native Windows, or Linux inside a WSL distribution. Nothing in this stack runs natively on Windows; inside WSL it also reports whether the working directory sits on a Windows drive (/mnt/...), which is read across a slow bridge and can make a run several times longer
- Nextflow, Java, and nf-core tools presence and versions
- Docker (installed + whether the daemon is running) and conda/mamba availability
- the container backend Bioinformática.org would use (Docker preferred, conda fallback)
- CPU cores and total/available memory
- GPU presence, VRAM, and driver

Alongside the report it returns a remediation plan: for each missing dependency, whether it can be installed without root and the exact command. It only recommends, it never runs anything.

Acting on the plan is a separate, approval-gated step you drive with other tools:
- For a step marked "install" (no root needed, e.g. Nextflow or nf-core tools): run its command through the shell/bash tool, which shows the command and asks for approval before running it. Never install silently.
- For a step marked "manual" (needs root, e.g. installing Docker or starting its daemon): show the command to the scientist and let them run it. Do not run privileged commands yourself.
- For a step marked "advice": nothing is missing and nothing has to be run. It is a property of this machine that will make a real run behave worse than expected, such as data sitting on a Windows drive under WSL. Say it to the scientist before a long run rather than after, and let them decide.
After applying fixes, call this tool again to confirm the environment is now ready.
